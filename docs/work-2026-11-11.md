# Work priorities — 2026-11-11

## Owner's primary product goal

Select many photos and videos, including large videos, and let Coolet organize their contents automatically. Bulk media handling and automatic organization are the core value, not manual descriptions. Owner requests leadership versus alternatives and substantial progress using capable relevant tools. Leadership is an ambition, not a verified claim; require comparative evidence before claiming it. Preserve all previous roadmap requirements and work.

## Implementation order and measurable acceptance

1. Reliable bulk import and persistent index. Initial test target: 1,000 mixed media items, including large videos. Measure actual device, item count, total bytes, maximum file size, elapsed time, memory and errors; do not call this target supported until tested.
2. Resilient work queue with bounded memory, visible progress, interruption/restart recovery and per-item retry. Preserve originals. Avoid whole-video memory loading. Current implementation does not yet provide persistent jobs or guaranteed recovery.
3. Automatic content analysis, categories and duplicate detection. Manual descriptions and filename matching do not satisfy this acceptance criterion.
4. Hebrew/English natural-language retrieval from the persistent index.
5. Test the complete import-to-organization-to-search workflow on real Android devices, then compare documented workloads against appropriate alternatives.

WhatsApp scope: user-accessible selected media only until a verified import mechanism exists. Do not claim whole-group access. No unapproved cloud media upload, paid API enrollment or third-party account setup.

## Implemented and verified so far

Local filename/description search supports all query terms in any order across both fields, Hebrew vowel/cantillation normalization and Unicode whitespace. Fourteen search regression checks plus Android lint/release build passed for commit d3c259ddf02ab4219a641a73040c153d1ef92d78 in run 42971993768.

Subsequent code adds bulk import progress every 25 processed items and a separate saving phase. This is progress reporting, not proof of large-import capacity or automatic organization.

Runtime CI was found to exercise the older distributed 0.2.3 APK. It now builds current source and records its APK digest, with cross-field/reversed-order/missing-term UI checks. Results for these changes remain pending. Do not count a legacy-APK run as validation of newer source.

## Open release boundaries

Large batch and large-video tests, persistent import jobs, automatic analysis/categorization, semantic search, duplicate-content detection, Hebrew UI, real-world playback, permission revocation and physical-phone checks remain open. No new signed user-installable APK has been delivered. The dist APK remains the old 0.2.3; emulator debug signing must not be offered as a compatible update to the user's preview.
